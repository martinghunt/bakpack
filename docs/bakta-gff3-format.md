# Bakta GFF3 output format

This describes the GFF3 that current Bakta (1.10.0 to 1.12.2 write the same)
writes for an annotation JSON, in its default mode and in `--compliant` mode,
as observed from its output. bakpack reproduces it byte for byte. It is a
description of the output only. The tests in `gff3_test.go` and
`testdata/bakta/` compare bakpack with GFF3 written by Bakta itself.

## Which JSON

The format applies to all Bakta JSON. JSON from Bakta before 1.10 uses an
older layout: features name their sequence with `contig` instead of
`sequence`, and sequences hold their nucleotides in `sequence` instead of
`nt`. It is written as current Bakta's `bakta_io` writes it, which can differ
from the GFF3 the older Bakta version wrote itself.

## Value formatting

Bakta formats values as Python's `str()` does after `json.load`:

- strings as they are
- `null` as `None`; `true` and `false` as `True` and `False`
- JSON numbers without `.`, `e` or `E` are integers, written in decimal
- other numbers are floats, written as Python's `repr(float)`: the shortest
  digits that round-trip, in fixed notation when the decimal exponent is from
  -4 to 15 (`0.0001`, `123.0`, `1234567890123456.0`; whole numbers get `.0`),
  otherwise in scientific notation with a sign and at least two exponent
  digits (`1e-05`, `1.2e-15`, `1e+16`, `1.2345678901234568e+16`)

"Truthy" below means Python truthiness: `null`, `false`, `""`, `0`, `[]` and
`{}` are false. Where this document says a feature "has" a key, only the key's
presence matters, not its value (this applies to `truncated`, `pseudogene`
and `edge`).

## Attributes (column 9)

Attributes are written as `key=value` joined by `;`, in the order each key was
first set. Setting a key again replaces its value in place; removing a key
deletes it. A value that is a list is written as its items joined by `,`, and
the attribute is left out entirely when the list is empty. Any other value is
formatted as above, so a `null` value is written as `None`. Within each value
or list item, exactly these characters are escaped: `%` as `%25`, `;` as
`%3B`, `=` as `%3D`, `&` as `%26`, `,` as `%2C`. Nothing else is escaped.

## File layout

Header lines:

1. `##gff-version 3`
2. `##feature-ontology https://github.com/The-Sequence-Ontology/SO-Ontologies/blob/v3.1/so.obo`
3. `# Generated by bakpack VERSION` (bakpack's own line; Bakta does not write
   it, and tests remove it before comparing)
4. `# organism TAXON`, only if `genome.taxon` is truthy
5. `# Annotated with Bakta`
6. `# Software: vVERSION` with `version.bakta`, only if that key is present
7. `# Database: vDBVERSION, DBTYPE`, only if `version.db` is an object.
   DBVERSION is `version.db.version` split on `.` and the first two parts
   rejoined with `.` (the whole value if it has no `.`); DBTYPE is
   `version.db.type`.
8. `# DOI: 10.1099/mgen.0.000685`
9. `# URL: github.com/oschwengers/bakta`

Then, for each entry of `sequences` in order:

- `##sequence-region ID 1 LENGTH`
- a region line: `ID`, `Bakta`, `region`, `1`, `LENGTH`, `.`, `+`, `.`,
  attributes `ID=ID;Name=ID`, plus `Is_circular=true` when `topology` is
  `circular`
- the features on that sequence, in JSON order

A feature belongs to the sequence named by its `sequence` key (`contig` in
older JSON). bakpack additionally writes features on sequence IDs that are not
in `sequences` after all sequences, grouped by ID in order of first
appearance.

Finally, unless in compliant mode or annotation-only output is requested:
`##FASTA`, then for each sequence `>ID` and its nucleotides (`nt`, or
`sequence` in the older layout) in lines of 60 characters. A sequence with no
nucleotides gets one empty line.

## Feature lines

Each feature line has nine tab-separated columns: the feature's sequence ID,
a source, a type, `start`, the stop, a score, the feature's `strand`, a phase,
and the attributes. The stop is `stop`, plus the sequence's `length` when the
feature has `edge` (a feature wrapping round the origin of a circular
sequence). Unless stated otherwise the score and phase are `.`.

In compliant mode several types first get a **gene line**: the same sequence
ID, source, start, stop and strand as the feature, type `gene`, score `.`,
phase `.`, and its own attributes. It is written immediately before the
feature line.

Shared compliant-mode steps used below:

- **INSDC Dbxrefs**: split `db_xrefs` (missing means empty) into those whose
  text before the first `:` is `UniProtKB/TrEMBL`, `GO`, `Pfam` or `RFAM`
  (valid), and the rest (invalid), each keeping its order. Set `Dbxref` to the
  valid list, then set `Note` to the invalid list.
- **Rfam inference**: for each Dbxref whose text before the first `:` is
  `RFAM`, set `inference` to `profile:Rfam:` followed by the text between the
  first and second `:` (or to the end). With several, the last wins.
- **EC numbers**: remove from `Note` every entry whose text before the first
  `:` is `EC`, and set `Note` again to the remaining entries. If any were
  removed, then set `ec_number` to the last one with every `EC:` removed.

### tRNA

Source `tRNAscan-SE`, type `tRNA`.

Attributes: `ID`=locus, `Name`=product, `locus_tag`=locus, `product`,
`Dbxref`=db_xrefs; `gene` if truthy; then `pseudogene=unknown` if the feature
has `pseudogene`, otherwise `pseudo=True` if it has `truncated`; `anti_codon`
if truthy; `amino_acid` if truthy.

Compliant: then `Parent`=locus + `_gene`, `inference=profile:tRNAscan:2.0`,
INSDC Dbxrefs. Gene line attributes: `ID`=locus + `_gene`, `locus_tag`, `gene`
if truthy, `pseudogene=unknown` if the feature has `pseudogene`.

### tmRNA

Source `Aragorn`, type `tmRNA`.

Attributes: `ID`, `Name`=product, `locus_tag`, `gene` (always, even when
null), `product`, `Dbxref`; `tag_peptide`=`tag.aa` if the feature has a `tag`
object; `pseudo=True` if it has `truncated`.

Compliant: then `Parent`, `inference=profile:aragorn:1.2`, INSDC Dbxrefs, and
if there is a `tag`, `tag_peptide` set again to `START..STOP` from
`tag.start` and `tag.stop`, wrapped as `complement(START..STOP)` unless the
feature strand is `+`. Gene line: `ID`, `locus_tag`, `gene` (always),
`pseudo=True` if `truncated`.

### rRNA

Source `Infernal`, type `rRNA`, score `evalue`.

Attributes: `ID`, `Name`=product, `locus_tag`, `gene` (always), `product`,
`Dbxref`; `pseudo=True` if `truncated`.

Compliant: then `Parent`, INSDC Dbxrefs, Rfam inference. Gene line: `ID`,
`locus_tag`, `gene` (always), `pseudo=True` if `truncated`.

### ncRNA

Source `Infernal`, type `ncRNA`, score `evalue`.

Attributes as for rRNA.

Compliant: then `Parent`, INSDC Dbxrefs, `ncRNA_class`, Rfam inference; then,
unless `gene` is a string consisting entirely of three lower case letters, an
upper case letter and an optional digit, remove `gene`. `ncRNA_class` comes
from the feature's `class`, which is `[NAME, SO_ID]` or null: `SO:0000644` is
`antisense_RNA`, `SO:0000374` is `ribozyme`, `SO:0000386` is `RNase_P_RNA`,
anything else (including null) is `other`. Gene line: `ID`, `locus_tag`,
`gene` (always, even when removed from the ncRNA line), `pseudo=True` if
`truncated`.

### ncRNA-region

Source `Infernal`, type `regulatory_region`, score `evalue`.

Attributes: `ID`=id (not locus), `Name`=product, `product`, `Dbxref`;
`pseudo=True` if `truncated`. No `locus_tag`.

Compliant (no gene line): then Rfam inference, INSDC Dbxrefs (in that order),
and `regulatory_class` from `class` by SO ID: `SO:0000140` `attenuator`,
`SO:0000035` `riboswitch`, `SO:0002168` `response_element`, `SO:1001268` or
`SO:0001427` `recoding_stimulatory_region`, `SO:0000139`
`ribosome_binding_site`, anything else (including `SO:0002205` and null)
`other`.

### CRISPR array (`crispr`)

Source `PILER-CR`, type `CRISPR` (compliant: `repeat_region`).

Attributes: `ID`=id, `Name`=product, `product`.

Compliant (no gene line): then
`inference=COORDINATES:alignment:pilercr:1.02`, INSDC Dbxrefs,
`rpt_family=CRISPR`, `rpt_type=direct`, `rpt_unit_seq`=repeat_consensus.

Default mode only, after the array line: for each index i from 0 while i is
below both the number of `spacers` and of `repeats`, a repeat line then a
spacer line; then, if the number of repeats minus one equals the number of
pairs written, one final repeat line. Repeat and spacer lines use the
feature's sequence ID, source `PILER-CR`, type `crispr-repeat` or
`crispr-spacer`, the repeat's or spacer's own `start`, `stop` and `strand`,
score `.` and phase `.`. Attributes: repeat `ID`=id + `_repeat_` + (i+1) and
`Parent`=id; spacer `ID`=id + `_spacer_` + (i+1), `Parent`=id and
`sequence`=the spacer's `sequence`; the final repeat has only `ID` (no
`Parent`).

### CDS (`cds`)

Source `?` if the feature's `source` is `user-provided`, otherwise
`Pyrodigal`. Type `CDS`, phase `0`.

Attributes: `ID`, `Name`=product, `locus_tag`, `product`, `Dbxref`; then
`pseudogene` if the feature has `pseudogene` (`unprocessed` if
`pseudogene.paralog` is truthy, otherwise `unitary`), otherwise `pseudo=True`
if it has `truncated`; then `gene` if truthy.

Compliant: then `Parent`, `inference` (`EXISTENCE:non-experimental evidence,
no additional details recorded` for user-provided, otherwise `ab initio
prediction:Pyrodigal:3.5`), INSDC Dbxrefs, EC numbers. Gene line: `ID`,
`locus_tag`, `gene` if truthy, and the same `pseudogene` value if the feature
has `pseudogene`.

In both modes, if the feature has an `exception` object:

- type `selenocysteine`: set `transl_except` to
  `(pos:START..STOP,aa:AA)` from the exception's `start`, `stop` and `aa`,
  with `START..STOP` wrapped as `complement(START..STOP)` when the feature
  strand is `-`; then set `Note` to its current list (empty if unset) with
  `codon on position CODON_POSITION is a TYPE codon` appended.
- type `ribosomal_slippage`: set `ribosomal_slippage=True`.

After the CDS line, a **signal peptide line** if the feature has a
`signal-peptide` object: the feature's sequence ID, `DeepSig`,
`signal_peptide`, the peptide's `start` and `stop`, its `score` with exactly
two decimals (Python `{:.2f}`), the feature strand, `.`, and attributes
`ID`=locus + `_sigpep`, `Name=signal peptide`, `product=signal peptide`,
`score`=the score formatted as a value, `Parent`=locus.

### sORF (`sorf`)

Source `Bakta`, type `CDS`, phase `0`.

Attributes: `ID`, `Name`=product, `locus_tag`, `product`, `Dbxref`; `gene` if
truthy. No pseudogene or truncation attributes, and exceptions are ignored.

Compliant: then `Parent`, INSDC Dbxrefs, EC numbers. Gene line: `ID`,
`locus_tag`, `inference=ab initio prediction:Bakta`, `gene` if truthy.

Then a signal peptide line as for CDS.

### Gap

Source `Bakta`, type `gap`. Attributes `ID`=id, `Name` and `product` both
`gap (LENGTH bp)` from `length`. The same in both modes.

### oriC, oriV, oriT

Source `BLAST+`. Type `oriT` for oriT; for oriC and oriV, `oriC` (compliant:
`rep_origin`).

Attributes: `ID`=id, `Name`=product; then in default mode `product` and
`inference=similar to DNA sequence`, in compliant mode `Note`=product.

## Compliant mode's annotation changes

Bakta's `--compliant` also changes the annotation before writing any file.
The JSON does not record whether it was used, so bakpack's compliant output
applies these changes itself. They leave JSON from a `--compliant` run
unchanged.

1. **Product names** of `cds` and `sorf` features (non-empty strings) are
   revised before use as `Name` and `product`: every case-insensitive
   occurrence of `uncharacterized` or `uncharacterised` becomes `putative`;
   then if the counts of `(` and `)` differ, all `(` and `)` are removed; then
   if the counts of `[` and `]` differ, all `[` and `]` are removed.
2. **Sequences shorter than 200** (by `length`) are left out, with their
   features, from the whole file.
3. **IDs INSDC would reject** cannot be fixed and are reported.

bakpack reports through `BaktaGFF3Options.Warn` (if set), in this order and
with these texts, where a list is the first five items joined by `, `, followed
by `, ...` when there are more:

- `left out N contig(s) shorter than 200 bp and their M feature(s), as Bakta --compliant does: LIST`
- `N contig ID(s) are not INSDC compliant (at most 25 characters from A-Z a-z 0-9 _ . : * # -): LIST`,
  for kept sequence IDs that are not 1 to 25 characters from
  `A-Z a-z 0-9 _ . : * # -`
- `locus tag prefix(es) are not INSDC compliant (3-12 upper case letters and digits, starting with a letter): LIST`,
  for distinct locus tag prefixes (the text before the last `_` of a
  feature's string `locus`, in order of first appearance) that are not an
  upper case letter followed by 2 to 11 upper case letters or digits

## Errors

- A feature whose `type` bakpack does not support: the existing unsupported
  feature type error.
- A feature with no sequence ID, `start` or `stop`: `feature ID is missing
  contig, start, or stop`.
- Compliant output for JSON from before Bakta 1.10 is refused in `gff3.go`.
